# Limits

Each limit cites the test that shows the behaviour, as `[T:file#title]`. `npm run docs:check` verifies every citation.

<!-- claims -->
- **A full re-hash forgery by someone with write access is not detected locally.** The chain, the head anchor and the reservation cross-check catch inconsistent edits [T:audit-tamper.test.mjs#head anchor removed and tail dropped]. An attacker who rewrites every row, every hash and the anchor consistently produces a valid-looking file. Detecting that needs an external anchor (e.g. publishing `exportChain()` heads elsewhere). The cited test shows the boundary: a forged anchor that no longer matches is caught.
- **Solana: settlement claims are held as unverified by the remote service.** The on-chain verifier is EVM/EIP-3009 only, and anything it can't check is not settled [T:audit-verify.test.mjs#no verifier: client-reported status is downgraded to unverified]. In-process, a Solana reservation settles only on a verified status [T:networks.test.mjs#Solana devnet: a reservation settles on a verified landed status], or is rejected up front when settlement is disabled [T:networks.test.mjs#settlement:false: cleanly rejected up front].
- **Facilitator rejections leave the reservation held.** When the facilitator refuses a payment (observed on Base Sepolia: `invalid_exact_evm_transaction_failed`, cause unconfirmed), the budget stays held until a verified `not_landed` arrives after `validBefore` [T:audit-verify.test.mjs#a false not_landed (authorization already used) cannot free the budget]. That is safe, but it uses budget. Workaround: wait for confirmation between calls.
- **Shared store: local disk only.** Shared mode serialises writers with SQLite WAL locks on one machine, and NFS or other network filesystems are not supported. Within one machine there is no double booking [T:audit-shared.test.mjs#4 processes x 60 contested keys]. A plain single-writer file refuses a second opener [T:audit-shared.test.mjs#a single-writer file still refuses a second opener].
- **A 30 s clock window for the remote service.** Requests whose timestamp differs from the server's by more than 30 s are refused [T:audit-remote.test.mjs#replay and stale timestamps are refused]. Replay nonces are held in memory for that window, so a service restart inside it forgets them. Idempotency keys still prevent a double booking [T:audit-shared.test.mjs#a retried open key reuses its reservation].
- **Node 22.13+ for SQLite and the server.** `x402-spotcheck/audit/sqlite` and `/audit/server` need `node:sqlite`. On older Node those tests skip and the in-memory default is unchanged [T:audit-sqlite.test.mjs#default is unchanged: no store, in memory]. The base package stays at engines >= 18.
- **A hold from a refused service response.** If the client refuses a response the service had already booked (e.g. a bad signature), the hold remains until it is released or reconciled [T:audit-remote.test.mjs#refuses: service down, slow (timeout), wrong pinned key, wrong client key].
- **Observe mode never blocks.** It logs would-be denials only [T:audit.test.mjs#observe logs the deny and does not reserve or abort].
- **Outages fail open below the threshold.** With `failClosedAboveAtomic` > 0, small payments go through during an audit outage [T:audit.test.mjs#outage fails closed above the threshold and open below it].
- **Unknown verdicts pay.** The spot-check is fail-open by default when it cannot read a 402 [T:v1.test.mjs#unknown means pay: unreadable 402].
- **v1 X-PAYMENT.** Header selection is tested [T:version-header.test.mjs#afterPay sends X-PAYMENT for a v1 payment header]. One live paid v1 self-test (402xAgent, Base mainnet, $0.02, 2026-10-20) settled and delivered. It is not a repeatable test, so no claim beyond header selection rests on it.
